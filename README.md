**Гаралтаас хаанаас уншсан бэ:**

**Ачаалал өсгөх (stages) ажиллуулалт:** `results/run-stages.txt`

## 3. SLO ба Thresholds (Алхам 4)

**Baseline (5 VU) p95 = \<___\> ms** → SLO-г `baseline p95 × 1.5 = <___>` ms болгон сонгов.

```js
thresholds: {
  http_req_duration: ['p(95)<___'],
  http_req_failed:   ['rate<0.01'],
}
```

**Яагаад энэ утга:** \<1-2 өгүүлбэр. Ж: Ачаалал багатай үеийн бодит p95-аас 50% зөрүүтэй босго нь сүлжээний ердийн хэлбэлзлийг тэвчих боловч бодит доройтлыг илрүүлэх хэмжээнд байна. Гадаад сайт руу зөвхөн TLS handshake л ~130ms болдог тул номноос авсан 300ms гэсэн утга миний нөхцөлд утгагүй.\>

| | Файл | Гаралт | Exit code |
| --- | --- | --- | --- |
| PASS | `thresholds-pass.js` | `results/run-threshold-pass.txt` | 0 |
| FAIL | `thresholds-fail.js` | `results/run-threshold-fail.txt` | 99 |

FAIL хувилбарт `p(95)<50` гэсэн санаатай хатуу босго тавьсан. CI pipeline дээр яг ийм байдлаар quality gate ажиллаж, босго хангагдаагүй үед build улаан болдог.
